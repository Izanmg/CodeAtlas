# Formato del índice de módulos

## Qué define este documento

Este documento especifica el formato del archivo `01-modules.md`, que actúa como índice general de módulos de la aplicación.

Además de listar los módulos existentes, este archivo es el lugar donde se declaran los **tipos de archivo válidos** para el proyecto. Esto permite que el parser conozca el vocabulario de tipos antes de leer los archivos de módulo individuales, y que cada proyecto pueda definir sus propios tipos según su stack tecnológico.

---

## Ubicación

```
project-docs/01-modules.md
```

---

## Formato completo

```markdown
---
type: modules-index
backend:
  - id: auth-backend
    name: Authentication
  - id: projects-backend
    name: Projects
  - id: diagrams-backend
    name: Diagrams
frontend:
  - id: auth-frontend
    name: Auth Views
  - id: projects-frontend
    name: Projects Views
  - id: settings-frontend
    name: Settings
file-types:
  backend:
    - controller
    - service
    - model
    - middleware
    - helper
    - repository
  frontend:
    - component
    - store
    - composable
    - view
    - helper
    - router
---

## Overview
Brief description of how the modules are organized and the overall architecture approach.
```

## Referencia de campos del frontmatter

| Campo | Tipo | Requerido | Descripción |
|-------|------|-----------|-------------|
| `type` | string | **sí** | Siempre `modules-index` |
| `backend` | lista de objetos | **sí** | Lista de módulos de backend. Cada objeto tiene `id` y `name`. El `id` debe coincidir con el nombre del archivo antes de `-backend-modules.md` |
| `frontend` | lista de objetos | **sí** | Lista de módulos de frontend. Cada objeto tiene `id` y `name`. El `id` debe coincidir con el nombre del archivo antes de `-frontend-modules.md` |
| `file-types` | objeto | **sí** | Declara los tipos de archivo válidos para este proyecto, separados por capa |
| `file-types.backend` | lista de strings | **sí** | Tipos válidos para el campo `type` en archivos de módulo de backend |
| `file-types.frontend` | lista de strings | **sí** | Tipos válidos para el campo `type` en archivos de módulo de frontend |

| Sección | Requerida | Contenido |
|---------|-----------|-----------|
| `## Overview` | **sí** | Descripción breve de cómo se organizan los módulos y el enfoque de arquitectura del proyecto |

## Tipos de archivo predefinidos

A continuación se listan los tipos más comunes por capa. Pueden usarse directamente o ampliarse según el stack del proyecto.

### Backend

| Tipo | Descripción |
|------|-------------|
| `controller` | Gestiona las peticiones HTTP y delega al servicio correspondiente |
| `service` | Contiene la lógica de negocio principal del módulo |
| `model` | Define la estructura de datos o entidad del módulo |
| `repository` | Gestiona el acceso a la base de datos |
| `middleware` | Lógica que se ejecuta entre la petición y el controlador |
| `helper` | Funciones auxiliares reutilizables dentro del módulo |

### Frontend

| Tipo | Descripción |
|------|-------------|
| `component` | Componente de interfaz reutilizable |
| `view` | Componente que representa una pantalla completa |
| `store` | Gestión del estado del módulo (Pinia, Vuex, Redux, etc.) |
| `composable` | Lógica reutilizable encapsulada (específico de Vue) |
| `hook` | Lógica reutilizable encapsulada (específico de React) |
| `helper` | Funciones auxiliares reutilizables dentro del módulo |
| `router` | Definición de rutas del módulo |

## Relación con los archivos de módulo

El campo `file-types` de este archivo define el vocabulario que el parser usa para validar el campo `type` de cada objeto en `files` dentro de los archivos de módulo individuales.

Si un archivo de módulo declara un `type` que no está en esta lista, el parser puede marcarlo como advertencia pero no fallará — el tipo se tratará como personalizado.

Esto permite que proyectos con stacks no convencionales puedan definir sus propios tipos sin restricciones, mientras que los tipos estándar quedan documentados y reconocidos por CodeAtlas.
