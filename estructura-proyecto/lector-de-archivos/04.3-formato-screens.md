# Formato de archivos de pantalla

## Qué define este documento

Este documento especifica el formato exacto que deben seguir los archivos de pantalla para que CodeAtlas pueda leerlos, interpretarlos y representarlos visualmente.

Las pantallas pertenecen exclusivamente al frontend. No existe división por capas.

---

## Reglas generales

- Cada archivo representa una única pantalla.
- Todos los archivos empiezan con un bloque de frontmatter YAML delimitado por `---`.
- El frontmatter contiene los campos estructurados que el parser usa para construir el diagrama.
- Después del frontmatter van las secciones Markdown con contenido descriptivo.
- Los campos de referencia (`module`, `folder`, `file`, `navigates-to`) usan IDs de otros archivos.
- Los IDs deben coincidir exactamente con el identificador del archivo o elemento al que apuntan.

---

## Ubicación

```
screens/{id}-screens.md
```

---

## Formato completo

```markdown
---
type: screen
id: login
name: Login
description: Entry point for unauthenticated users
module: auth-frontend
folder: views
file: login-view
requires-auth: false
routes:
  - /auth/login
  - /login
navigates-to: [dashboard]
components:
  - LoginForm
  - ErrorMessage
---

## Description
Detailed description of what the screen shows and its purpose within the application.

## Elements
- username input
- password input
- submit button
- link to register screen

## Actions
- submit-login
- go-to-register

## States
- default
- loading
- error
```

---

## Referencia de campos del frontmatter

| Campo | Tipo | Requerido | Descripción |
|-------|------|-----------|-------------|
| `type` | string | **sí** | Siempre `screen` |
| `id` | string | **sí** | Identificador único de la pantalla. Debe coincidir con el nombre del archivo antes de `-screens.md` |
| `name` | string | **sí** | Nombre legible de la pantalla |
| `description` | string | **sí** | Descripción breve en una línea |
| `module` | ID | **sí** | ID del módulo frontend al que pertenece esta pantalla. Apunta a `modules/frontend/{id}-frontend-modules.md` |
| `requires-auth` | boolean | **sí** | Indica si la pantalla requiere que el usuario esté autenticado. Permite representar visualmente qué pantallas son públicas y cuáles protegidas |
| `folder` | ID | no | ID de una carpeta declarada en `folders` del módulo referenciado. Indica en qué subcarpeta del módulo vive esta pantalla |
| `file` | ID | no | ID de un archivo declarado en `files` del módulo referenciado. Vincula la pantalla con el archivo de código que la implementa. Permite al parser establecer la conexión en los dos sentidos: desde el módulo hacia la pantalla y desde la pantalla hacia el módulo |
| `routes` | lista de strings | no | Rutas URL que renderizan esta pantalla |
| `navigates-to` | lista de IDs | no | IDs de pantallas a las que puede navegar esta pantalla. Cada ID apunta a `screens/{id}-screens.md` |
| `components` | lista de strings | no | Nombres de los componentes usados en esta pantalla. Son nombres de componente, no IDs de archivo |

---

## Referencia de secciones Markdown

| Sección | Requerida | Contenido |
|---------|-----------|-----------|
| `## Description` | **sí** | Descripción detallada de qué muestra la pantalla y qué papel cumple en la aplicación |
| `## Elements` | no | Elementos de interfaz presentes en la pantalla |
| `## Actions` | no | Acciones que puede realizar el usuario desde esta pantalla |
| `## States` | no | Estados posibles de la pantalla (default, loading, error, empty, etc.) |

---

## Cómo funcionan las referencias

| Campo | Dónde busca el parser |
|-------|----------------------|
| `module` | `modules/frontend/{id}-frontend-modules.md` |
| `folder` | Lista `folders` dentro del módulo referenciado por `module` |
| `file` | Lista `files` dentro del módulo referenciado por `module` |
| `navigates-to` | `screens/{id}-screens.md` por cada ID de la lista |

### Vínculo entre pantalla y archivo de módulo

El campo `file` establece una conexión bidireccional entre la pantalla y el archivo de código que la implementa:

- **Desde el módulo**: el archivo declarado con `type: view` o `type: component` sabe que tiene una pantalla documentada asociada.
- **Desde la pantalla**: el archivo `screens/login-screens.md` sabe exactamente a qué archivo del módulo corresponde.

Esto permite al parser representar la jerarquía completa:

```
módulo frontend (auth-frontend)
└── carpeta (folder: views)
    └── archivo (file: login-view, type: view)
            ↕ vinculado
        pantalla (screen: login)
```

## Ejemplos según nivel de detalle

### Mínimo (solo campos obligatorios)

```markdown
---
type: screen
id: login
name: Login
description: Entry point for unauthenticated users
module: auth-frontend
requires-auth: false
---

## Description
Allows unauthenticated users to log in with their username and password.
```

### Medio (con rutas y navegación)

```markdown
---
type: screen
id: login
name: Login
description: Entry point for unauthenticated users
module: auth-frontend
requires-auth: false
routes:
  - /auth/login
  - /login
navigates-to: [dashboard, register]
---

## Description
Allows unauthenticated users to log in with their username and password.

## Actions
- submit-login
- go-to-register
```

### Completo (con vínculo al archivo de módulo y detalle de interfaz)

```markdown
---
type: screen
id: login
name: Login
description: Entry point for unauthenticated users
module: auth-frontend
folder: views
file: login-view
requires-auth: false
routes:
  - /auth/login
  - /login
navigates-to: [dashboard, register]
components:
  - LoginForm
  - ErrorMessage
---

## Description
Allows unauthenticated users to log in with their username and password.
Redirects authenticated users directly to the dashboard.

## Elements
- username input
- password input
- submit button
- link to register screen

## Actions
- submit-login
- go-to-register

## States
- default
- loading
- error
```
