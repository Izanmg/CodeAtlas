# Formato del archivo de reglas del sistema

## Qué define este documento

Este documento especifica el formato del archivo `05-system-rules.md`, que recoge las reglas globales y decisiones técnicas transversales de la aplicación.

A diferencia de los otros bloques documentales, este archivo no tiene una carpeta asociada ni archivos de detalle. Todo el contenido vive en un único documento, ya que las reglas del sistema aplican de forma global y no tiene sentido fragmentarlas por elemento.

---

## Ubicación

```
project-docs/05-system-rules.md
```

---

## Formato completo

```markdown
---
type: system-rules
---

## Auth
- All routes require authentication except /auth/login and /auth/register
- Sessions expire after 24 hours of inactivity
- Two roles exist: user and admin
- Admin routes are prefixed with /admin

## Navigation
- Unauthenticated users are redirected to /login regardless of the requested route
- After a successful login, users are redirected to /dashboard
- After logout, users are redirected to /login

## Validation
- Passwords must be at least 8 characters and contain at least one number
- Usernames must be unique, between 3 and 30 characters, alphanumeric with underscores allowed
- All dates are sent from the frontend in ISO 8601 format

## Conventions
- API responses always use camelCase for field names
- All timestamps are stored and returned in UTC
- HTTP error responses always include a `message` field with a human-readable explanation
- Frontend stores the session token in localStorage under the key `auth_token`

## Technical Decisions
- Session tokens are JWT signed with HS256 and expire after 24 hours
- Passwords are always hashed with bcrypt (cost factor 12) before storage
- The frontend never stores plain-text passwords, not even temporarily
```

---

## Referencia de campos del frontmatter

| Campo | Tipo | Requerido | Descripción |
|-------|------|-----------|-------------|
| `type` | string | **sí** | Siempre `system-rules` |

El frontmatter de este archivo es intencionalmente mínimo. Su valor es descriptivo, no estructural: el parser lo usa para identificar el tipo de archivo, pero el contenido útil está en las secciones Markdown.

---

## Referencia de secciones Markdown

Las secciones de este archivo son **completamente libres**. No hay secciones obligatorias ni un conjunto fijo de nombres. Cada proyecto define las secciones que necesita según las reglas que quiere documentar.

Las siguientes son sugerencias habituales, no requisitos:

| Sección sugerida | Contenido |
|-----------------|-----------|
| `## Auth` | Qué rutas requieren autenticación, roles existentes, comportamiento de sesión |
| `## Navigation` | Redirecciones automáticas, comportamiento tras login/logout, rutas por rol |
| `## Validation` | Reglas de validación globales aplicadas en frontend o backend |
| `## Conventions` | Convenciones de código, formato de respuesta de API, nombres de campos |
| `## Technical Decisions` | Decisiones de arquitectura o tecnología que afectan a todo el sistema |

El contenido de cada sección puede ser texto libre, listas de puntos, o cualquier combinación.

---

## Diferencia con las notas en módulos o flujos

Los archivos de módulo (`04.1`) y de flujo (`04.4`) tienen una sección `## Notes` opcional para decisiones técnicas específicas de ese módulo o flujo. `05-system-rules.md` es diferente:

- **`## Notes` en módulos y flujos**: decisiones que afectan solo a ese módulo o flujo concreto.
- **`05-system-rules.md`**: reglas y decisiones que afectan a toda la aplicación y no tienen un sitio más específico donde documentarse.

Si una regla aplica solo a un módulo, va en ese módulo. Si aplica a toda la aplicación, va aquí.

## Ejemplos según nivel de detalle

### Mínimo


### Completo

```markdown
---
type: system-rules
---

## Auth
- All routes require authentication except /auth/login and /auth/register
- Sessions expire after 24 hours of inactivity
- Two roles exist: user and admin
- Admin routes are prefixed with /admin and require role: admin

## Navigation
- Unauthenticated users are redirected to /login regardless of the requested route
- After a successful login, users are redirected to /dashboard
- After logout, users are redirected to /login

## Validation
- Passwords must be at least 8 characters and contain at least one number
- Usernames must be unique, between 3 and 30 characters, alphanumeric with underscores allowed
- All dates are sent from the frontend in ISO 8601 format (YYYY-MM-DD)

## Conventions
- API responses always use camelCase for field names
- All timestamps are stored and returned in UTC
- HTTP error responses always include a `message` field with a human-readable explanation
- Frontend stores the session token in localStorage under the key `auth_token`

## Technical Decisions
- Session tokens are JWT signed with HS256 and expire after 24 hours
- Passwords are always hashed with bcrypt (cost factor 12) before storage
- The frontend never stores plain-text passwords, not even temporarily
- File uploads are validated by MIME type and limited to 10 MB
```
