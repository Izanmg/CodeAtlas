# Formato de archivos de entidad de base de datos

## Qué define este documento

Este documento especifica el formato exacto que deben seguir los archivos de entidad de base de datos para que CodeAtlas pueda leerlos, interpretarlos y representarlos visualmente.

Las entidades pertenecen exclusivamente al backend. No existe división por capas.

---

## Reglas generales

- Cada archivo representa una única entidad (tabla o colección).
- Todos los archivos empiezan con un bloque de frontmatter YAML delimitado por `---`.
- El frontmatter contiene los campos estructurados que el parser usa para construir el diagrama.
- Después del frontmatter van las secciones Markdown con contenido descriptivo.
- El campo `used-by` usa IDs de módulos de backend.
- El campo `relations` usa IDs de otras entidades.
- Los IDs deben coincidir exactamente con el identificador del archivo al que apuntan.

---

## Ubicación

```
database/{id}-database.md
```

---

## Formato completo

```markdown
---
type: entity
id: users
name: User
description: Stores registered user accounts
used-by: [auth-backend, projects-backend]
relations:
  - target: projects
    type: one-to-many
    field: user_id
  - target: sessions
    type: one-to-many
    field: user_id
---

## Table

```dbml
Table users {
  id uuid [pk]
  username varchar [not null, unique]
  password_hash varchar [not null]
  birth_date date
  created_at timestamp [not null]
  updated_at timestamp [not null]
}

Ref: users.id < projects.user_id
Ref: users.id < sessions.user_id
```

## Notes
Passwords are never stored in plain text. The password_hash field always stores a bcrypt hash.
```

---

## Referencia de campos del frontmatter

| Campo | Tipo | Requerido | Descripción |
|-------|------|-----------|-------------|
| `type` | string | **sí** | Siempre `entity` |
| `id` | string | **sí** | Identificador único de la entidad. Debe coincidir con el nombre del archivo antes de `-database.md` |
| `name` | string | **sí** | Nombre legible de la entidad |
| `description` | string | **sí** | Descripción breve en una línea |
| `used-by` | lista de IDs | no | IDs de módulos de backend que leen o modifican esta entidad. Cada ID apunta a `modules/backend/{id}-backend-modules.md` |
| `relations` | lista de objetos | no | Relaciones de esta entidad con otras. Ver formato detallado más abajo |

---

## Formato del campo `relations`

Cada objeto de `relations` describe una relación con otra entidad:

```yaml
relations:
  - target: projects
    type: one-to-many
    field: user_id
```

| Campo | Requerido | Descripción |
|-------|-----------|-------------|
| `target` | **sí** | ID de la entidad destino. Apunta a `database/{id}-database.md` |
| `type` | **sí** | Tipo de relación: `one-to-one`, `one-to-many`, `many-to-many` |
| `field` | no | Nombre del campo que actúa como clave foránea en la relación |

---

## Referencia de secciones Markdown

| Sección | Requerida | Contenido |
|---------|-----------|-----------|
| `## Table` | **sí** | Definición de la tabla en formato DBML dentro de un bloque de código ` ```dbml ` |
| `## Notes` | no | Decisiones técnicas relevantes sobre esta entidad |

---

## Formato DBML

El bloque `## Table` usa [DBML (Database Markup Language)](https://dbml.dbdiagram.io/docs/) para describir la estructura de la entidad.

### Tipos de datos comunes

| Tipo | Descripción |
|------|-------------|
| `int` | Entero |
| `bigint` | Entero grande |
| `float` | Número decimal |
| `boolean` | Verdadero o falso |
| `varchar` | Cadena de texto variable |
| `text` | Texto largo |
| `uuid` | Identificador único universal |
| `date` | Solo fecha |
| `timestamp` | Fecha y hora |
| `json` | Objeto JSON |

### Atributos de columna comunes

| Atributo | Descripción |
|----------|-------------|
| `[pk]` | Clave primaria |
| `[not null]` | No puede ser nulo |
| `[unique]` | Valor único en la tabla |
| `[default: valor]` | Valor por defecto |
| `[ref: > tabla.campo]` | Clave foránea (relación many-to-one) |

### Relaciones en DBML

Las relaciones se definen con `Ref` fuera de la tabla:

```dbml
Ref: tabla_origen.campo > tabla_destino.campo   // many-to-one
Ref: tabla_origen.campo < tabla_destino.campo   // one-to-many
Ref: tabla_origen.campo - tabla_destino.campo   // one-to-one
```

---

## Cómo funcionan las referencias

| Campo | Dónde busca el parser |
|-------|----------------------|
| `used-by` | `modules/backend/{id}-backend-modules.md` |
| `relations[].target` | `database/{id}-database.md` |

## Ejemplos según nivel de detalle

### Mínimo (solo campos obligatorios)

```markdown
---
type: entity
id: users
name: User
description: Stores registered user accounts
---

## Table

```dbml
Table users {
  id uuid [pk]
  username varchar [not null, unique]
  password_hash varchar [not null]
  created_at timestamp [not null]
}
```
```

### Medio (con módulos que la usan y relaciones)

```markdown
---
type: entity
id: users
name: User
description: Stores registered user accounts
used-by: [auth-backend]
relations:
  - target: projects
    type: one-to-many
    field: user_id
---

## Table

```dbml
Table users {
  id uuid [pk]
  username varchar [not null, unique]
  password_hash varchar [not null]
  birth_date date
  created_at timestamp [not null]
  updated_at timestamp [not null]
}

Ref: users.id < projects.user_id
```
```

### Completo (con relaciones múltiples, valores por defecto y notas)

```markdown
---
type: entity
id: users
name: User
description: Stores registered user accounts
used-by: [auth-backend, projects-backend]
relations:
  - target: projects
    type: one-to-many
    field: user_id
  - target: sessions
    type: one-to-many
    field: user_id
---

## Table

```dbml
Table users {
  id uuid [pk]
  username varchar [not null, unique]
  password_hash varchar [not null]
  birth_date date
  role varchar [not null, default: 'user']
  created_at timestamp [not null]
  updated_at timestamp [not null]
}

Ref: users.id < projects.user_id
Ref: users.id < sessions.user_id
```

## Notes
Passwords are never stored in plain text. The password_hash field always stores a bcrypt hash.
The role field accepts: 'user', 'admin'.
```
