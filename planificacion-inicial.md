# Planificación inicial de CodeAtlas

Este documento sirve como base para organizar el proyecto, preparar el diagrama de Gantt y tener un listado claro de todo lo que hay que hacer hasta la entrega.

## 1. Lista general de trabajo

### Definición y análisis
- cerrar la idea final del proyecto
- definir el alcance real del MVP
- fijar requisitos funcionales
- fijar requisitos no funcionales
- definir casos de uso y/o UML
- revisar que el alcance cumpla los mínimos del proyecto de síntesis
- asegurar que la aplicación incluya un sistema de gestión vía web
- asegurar que el proyecto mantenga un enfoque original y defendible
- planificar ampliaciones futuras y mantenimiento aunque no todo se llegue a implementar

### Diseño del producto
- definir cómo será la experiencia de usuario
- definir pantallas principales
- definir flujo de navegación
- definir formato `.md` que leerá CodeAtlas
- definir cómo se transformará ese contenido en representación visual

### Diseño técnico
- decidir stack final de frontend
- decidir stack final de backend
- definir estructura del proyecto
- definir modelo de base de datos con al menos 3 entidades/colecciones relacionadas
- definir API o web services necesarios
- definir integración mínima de IA
- definir estrategia de autenticación
- definir separación clara entre parte cliente y parte servidor

### Desarrollo del MVP
- preparar estructura base del proyecto
- configurar frontend
- configurar backend
- configurar base de datos
- implementar autenticación y registro
- implementar subida/lectura de archivos `.md`
- implementar parser del formato `.md`
- implementar representación visual en web
- conectar frontend, backend y base de datos

### Desarrollo de la aplicación completa
- desarrollar la funcionalidad de análisis de aplicaciones ya creadas
- detectar estructura de archivos y módulos
- detectar funciones, clases y relaciones
- detectar imports, usos y conexiones entre partes del proyecto
- transformar ese análisis en un formato entendible por CodeAtlas
- representar visualmente también esa segunda parte dentro de la interfaz web
- integrar la funcionalidad basada en documentación y la funcionalidad basada en análisis de código

### Calidad, pruebas y seguridad
- planificar tests
- probar funcionalidades principales
- revisar errores
- validar HTML y comportamiento responsive / multidispositivo
- revisar seguridad básica
- comprobar robustez frente a fallos o ataques comunes
- comprobar uso por HTTPS en despliegue
- asegurar acceso seguro al servidor por SSH

### Despliegue
- preparar entorno de producción
- desplegar la aplicación
- verificar URL final
- documentar la plataforma de desarrollo y producción

### Documentación de entrega
- elaborar memoria
- elaborar manual técnico
- elaborar manual de usuario
- preparar anexos
- preparar guion de exposición
- preparar presentación multimedia
- revisar que la presentación cumpla la norma de no abusar del texto en diapositivas
- preparar versión final en PDF o formato entregable
- subir o dejar listo el material para Moodle / nube si hiciera falta

### Seguimiento y defensa
- mantener planificación semanal
- registrar lo hecho cada semana y lo previsto para la siguiente
- registrar dedicación real y avances del trabajo durante el proceso
- comparar planificación inicial con evolución real
- preparar discurso de defensa
- ensayar exposición
- preparar defensa individual de cualquier parte del proyecto
- cuidar el punto de innovación que también cuenta en la evaluación

## 4. Enfoque real del proyecto

Aunque el MVP inicial se centrará en la lectura de archivos `.md` para representar visualmente la aplicación cuanto antes, el objetivo del proyecto no es quedarse solo en esa parte.

La meta es llegar al 22 de mayo con la aplicación completa, incluyendo también la funcionalidad orientada a visualizar aplicaciones ya creadas.

Por tanto, el MVP se entiende como una primera fase para asegurar una base funcional pronto, pero no como el alcance final del proyecto.
